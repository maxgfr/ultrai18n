# Add a locale without rewriting its source

Use this route when the user wants a new locale catalog and the source language
must remain unchanged. The byte-offset writer edits the paths it scanned; it
does not infer a destination filename from a translation request.

1. Record the source catalog's hash. Create a disposable Git repository containing
   a byte-identical source catalog and a copy at the target locale's path. For
   example, retain `locales/en.json` and seed `locales/fr.json` from its bytes.
   Copy through filesystem tools; the translator does not read source files.
   Commit this staging baseline so the writer's VCS guard can operate.
2. Put the engine run directories **outside** that staging repository. Results,
   backups and verdicts must not become new translation inputs. Keep the source
   and target locale paths recognizable to `catalog --explain`.
3. Run the normal engine against staging. Below, `ENGINE` is the absolute bundled
   script path; `STAGE`, `RUN` and `POST` are distinct absolute directories.

```sh
node "$ENGINE" scan --repo "$STAGE" --from en --to fr --out "$RUN" --json
node "$ENGINE" plan --repo "$STAGE" --out "$RUN" --mode swap --json
node "$ENGINE" translate --repo "$STAGE" --out "$RUN" --backend manual --json
# Give the translator only the emitted batches and their contract.
# Collect its results under RUN/results, preserving batch identity and limits.
node "$ENGINE" translate --repo "$STAGE" --out "$RUN" --apply "$RESULT" --json
node "$ENGINE" apply --repo "$STAGE" --out "$RUN" --write --json
node "$ENGINE" scan --repo "$STAGE" --from en --to fr --out "$POST" --json
node "$ENGINE" plurals --repo "$STAGE" --out "$POST" --json
node "$ENGINE" sync --repo "$STAGE" --out "$POST" --source-locale en --json
```

These are sequential stages: stop on a failed command. Set `RESULT` to the
actual result file; repeat the fold for every batch. Require zero rejected,
refused, missing and incomplete items before applying. A partially accepted
batch can still yield a successful `apply`; that is not a complete translation.
Respect the emitted `max` and target plural categories. For example, French can
require `many` in addition to `one` and `other`; keep the engine's family contract.

Rescan after applying: the original inventory describes the old catalog.
`sync` with `baselineOnly: true` checks current catalogs but cannot prove historical
freshness. Never manufacture a historical state file to remove that limitation.
Complete the normal semantic review before claiming translation quality; JSON,
placeholder and plural checks alone establish structural properties.

Before copying the finished target into the user's repository, verify the source
hash is unchanged, all requested target keys exist, placeholders are preserved,
and only the staged target was modified. Copy the engine-generated bytes with
exclusive creation: refuse an existing destination, including a symlink. An
existing target needs a merge/sync decision, not silent replacement. Report the
catalog scope and any remaining checks; this route makes no repository-wide
translation-completeness claim.
